# PixelTank

Многопользовательская Canvas-игра про танки. Сервер рассчитывает физику и попадания, браузер рисует мир и предсказывает движение между обновлениями. Боты подключаются как обычные игроки через WebSocket.

## Запуск

Требуется Bun 1.4.2 или совместимая более новая версия. Node.js и Gulp не нужны.

```sh
bun install
bun run dev
```

Откройте http://localhost:9080. Одна команда запускает сервер, сборку клиента и отдельный процесс с двумя ботами. Изменения клиента автоматически пересобирают его и обновляют страницу; изменения серверного кода или ботов перезапускают процессы. Изменения общего пакета обновляют обе стороны. Наблюдение сравнивает содержимое файлов каждые 500 мс, чтобы события файловой системы macOS не вызывали повторную сборку без изменений.

```sh
bun run start        # сборка и запуск без наблюдения, с двумя ботами
bun run build        # только браузерная сборка в dist/
bun run format       # форматирование TypeScript
bun run check        # строгая проверка всех TypeScript-окружений
bun test             # модели, физика, WebSocket, боты и запуск процессов
BOT_COUNT=0 bun run dev
PORT=9000 BOT_COUNT=5 bun run start
```

Ctrl+C завершает сервер и ботов. Ошибка дочернего процесса завершает весь запуск с ненулевым кодом. Занятый порт диагностируется до запуска процессов. Тесты открывают локальные порты; их следует выполнять в окружении, где это разрешено.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Адрес прослушивания; `0.0.0.0` для игры по локальной сети |
| `PORT` | `9080` | HTTP и WebSocket на одном порту |
| `BOT_COUNT` | `2` | Количество ботов, целое неотрицательное число |
| `SERVER_URL` | `ws://localhost:9080/ws` | Адрес для самостоятельного запуска ботов |

Самостоятельный запуск частей:

```sh
bun run build
bun server/src/main.ts
SERVER_URL=ws://localhost:9080/ws BOT_COUNT=2 bun bots/src/main.ts
```

При запуске через корневой скрипт `SERVER_URL` для ботов определяется из `HOST` и `PORT`. Браузер подключается к `/ws` на адресе открытой страницы, используя `wss:` для HTTPS. Изменение зависимостей требует повторного `bun install`, изменение скриптов запуска — повторного запуска команды.

## Управление

- WASD — движение и поворот корпуса.
- Мышь — направление башни; левая кнопка — стрельба.
- Колесо мыши — масштаб 0.5–1.4.
- Удерживать Q — таблица статистики.

Доступны лёгкий, средний и тяжёлый танки с исходными характеристиками и графикой. После смерти танк автоматически возрождается в случайной точке с полным здоровьем; выбранный тип и статистика игрока сохраняются до отключения. Переподключение создаёт новую сессию с прежним именем и типом танка, но без старых очков.

## Архитектура

```text
client/src/   GameClient, InputController, Camera, Renderer, AssetLoader, network Worker, render Worker
server/src/   GameServer, GameWorld, PhysicsWorld (адаптер p2)
bots/src/     BotRunner, BotClient, BotStrategy, NearestTargetStrategy
shared/src/   Tank, Bullet, DTO, настройки, математика и WebSocket-протокол
scripts/      сборка и управление процессами
tests/        модульные и интеграционные проверки
```

`client`, `server` и `bots` зависят только от `shared`, без импортов друг друга. Общий пакет не зависит от DOM, Bun или p2; сетевой клиент использует переданные транспорт и планировщик. Игрок хранит имя, выбранный тип танка и статистику, танк — состояние текущей жизни. Физические тела существуют только на сервере. DTO содержат обычные данные; для танков и снарядов предусмотрены явные копирующие преобразования.

Отрисовка выполняется отдельным Worker через OffscreenCanvas: один canvas для фона, игровых объектов, миникарты, статистики и журнала. Сетевой Worker работает независимо. Главный поток обрабатывает DOM, ввод и размеры окна; предсказание движения и requestAnimationFrame находятся в render Worker. Требуется поддержка OffscreenCanvas 2D и requestAnimationFrame в Worker.

Размер буфера canvas равен размеру окна в CSS-пикселях, умноженному на devicePixelRatio (с округлением до целого). Камера, HUD и прицеливание используют CSS-пиксели. Изменение масштаба браузера или перенос на другой экран обновляет DPR через matchMedia и resize; SVG-спрайты заново растеризуются с новой плотностью и передаются как ImageBitmap. Старые bitmap освобождаются при замене.

Фиксированный шаг сервера — 60 Гц; снимки мира — 21 Гц; статистика — раз в 750 мс. Клиент ограничивает предсказание 250 мс при задержке сети. Границы мира едины: x/y от -2560 до 2530, по исходным серверным стенам. Сервер остаётся единственным источником результатов попаданий, здоровья и счёта.

JSON-протокол версии 1:

- Клиент → сервер: `join` (имя, тип танка), `input` (движение, поворот, угол, стрельба).
- Сервер → клиент: `welcome` (ID, версия, конфигурация), `snapshot` (тик, игроки, танки, снаряды), `stats`, `death`, `error`.
- Входящие команды проверяются во время выполнения. Повторный вход не создаёт дубликаты.
- Переподключение: задержка от 250 мс до 5 секунд, сброс задержки после `welcome`.

Исправлены смерть при точном обнулении HP, геометрия попадания в повёрнутый танк, пропуски при удалении снарядов, очистка физических тел, определение собственного игрока, торможение и сброс управления при потере фокуса. Изменён сетевой протокол: старые Socket.IO-клиенты несовместимы. Постоянного хранения статистики нет.

## Проверка перед изменениями

`bun run check`, `bun test` и `bun run build` должны проходить. Тесты проверяют характеристики всех танков, повороты, перезарядку, p2-границы, смерть/возрождение, очистку объектов, сообщения реального WebSocket, стратегию и переподключение ботов, режимы запуска и остановку процессов. Тесты запуска выполняют сборку, поэтому запускайте их отдельно от активного dev-сеанса.

Для визуальной проверки: откройте две вкладки, выберите разные танки, проверьте движение, стрельбу, масштаб, миникарту, таблицу Q, журнал убийств и переподключение при перезапуске сервера.
